Mintlify's pitch is "the knowledge infrastructure agents build on". This page separates that pitch into concrete features, says which plan each needs, which we would realistically use, and what has been prepared in this repository so the hosted demo is a matter of deploying.

<Warning>
**None of these features run in the local preview.** `mint dev` serves neither `/llms.txt`, page `.md` URLs, `/mcp`, the assistant, feedback nor analytics — all return 404 locally. The July trial deployment (`llamaindex-0863d802.mintlify.io`) has since been removed, so the demo needs a fresh hosted deployment of this repo.
</Warning>

## Baseline: how the current site scores today

Mintlify's public [Agent Score](https://www.mintlify.com/score/developers.llamaindex.ai) grades **developers.llamaindex.ai at 79/100 (C)** — 16 of 30 checks passed, 6 failed, 3 warnings. The failing categories are *Markdown availability*, *Full content discoverability* (`llms-full.txt`), *Agent skills* (`skill.md`), *URL stability and redirects*, *Content discoverability* and *Observability*. Four of those six are things a Mintlify deployment provides without any work; this makes a clean before/after for the demo.

Enterprise pricing is custom.

## What's prepared in this repository

- `docs.json` → `contextual.options` now includes `assistant` (Ask AI on every page) and `add-mcp` (one-click MCP install) alongside copy / view-as-markdown / ChatGPT / Claude / Perplexity / Cursor / VS Code.
- `.mintlify/Assistant.md` — custom assistant instructions: persona, v2-first SDK guidance (never recommend `llama-cloud-services` unless asked about v1), tier and version-pinning rules, escalation to support.
- `.mintlify/assistant/skills/{llamaparse,liteparse,llamacloud-index}/skill.md` — our three published agent skills (MIT), so the assistant loads them for matching questions and the MCP server exposes them as resources.
- `<Visibility for="agents">` blocks on the home page and Getting started: agent-facing pointers to `.md` URLs, `/llms.txt`, `/mcp`, the skills installer and the minimal REST sequence.
- 40 redirects and a clean link graph (the *URL stability* check).
- The changelog with RSS, and the OpenAPI-generated reference (which the MCP server can search).

## Demo script for the hosted trial

1. **Deploy** this repo through the Mintlify GitHub app; note the subdomain (it will be `*.mintlify.io`, not `.site`).
2. **Run Agent Score** on the new subdomain and put it next to the 79/C baseline.
3. **Markdown for agents:** open any page with `.md` appended; open `/llms.txt` and `/llms-full.txt`.
4. **MCP:** use the page's "Add MCP" action to install the server in Claude Desktop or Cursor; ask it a Parse question and watch it call `search`; then ask it to file feedback and check the dashboard for the "Agent" badge.
5. **Ask AI:** enable the assistant (Pro trial); ask the three starter questions we'd configure — "How do I pin a Parse version?", "Which tier should I use for scanned forms?", "How do I migrate from v1?" — and check that answers cite pages and prefer the v2 SDK (that is what `Assistant.md` is for). Then ask a LiteParse question to see the skill load.
6. **Analytics:** after a day of use, review human vs agent traffic, assistant transcripts and no-result searches.
7. **Automations:** enable *Fix broken links* (content-update trigger) and *Update from code changes* pointed at `run-llama/platform`; merge one real Parse change upstream and judge the PR it opens. This is the make-or-break test — Jack's "Draft feature docs" pitch lives here.

## What this doesn't answer

Answer quality of the assistant and automations, agent-feedback volume, and whether 10,000 credits is realistic for our traffic can only be measured on the hosted deployment over time. Those are the open items on the [checklist](/evaluation/checklist).
